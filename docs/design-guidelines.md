# 设计规范

## 选项控件

**配置项的选项数量小于等于 4 项时，必须使用 radio box（单选按钮）；5 项或更多时才使用下拉框。**

这条规则适用于所有配置项，包括全局设置和每条服务器的协议字段。

| 选项数 | 控件 | 示例 |
| --- | --- | --- |
| ≤ 4 | Radio box | 日志级别（4）、传输（4）、安全（3）、Flow（2）、域名解析策略（4） |
| ≥ 5 | 下拉框 | 协议（13）、uTLS 指纹（10）、VMess 加密方式（5） |

实现时统一走 `main.go` 的 `renderChoice`，不要在业务代码里直接写 `ui.Select` 或 `ui.RadioGroup`。

## 服务器列表交互

- 单击只选中，不激活；双击打开该服务器的编辑窗口；回车把选中的服务器设为当前。
- 编辑窗口是独立的非模态窗口，每条服务器一个，允许同时打开多个。
- 编辑窗口只放协议表单和保存 / 取消，启动、停止、全局设置留在主窗口。
- 多选（Cmd / Ctrl / Shift 点击）后，复制和删除按批量处理。

## 窗口与托盘

- 关闭主窗口不退出程序，而是隐藏到菜单栏 / 通知区域，代理继续运行。
- 托盘图标左键显示或隐藏主窗口，右键菜单至少包含「显示主窗口」和「退出」。
- 只有真正退出时才停止内核并销毁托盘图标。
- 托盘创建失败时不要拦截窗口关闭，否则用户可能再也找不回窗口。

## 布局与文案

- 配置项用 `ui.Field` 包裹标签和控件。
- 界面文案使用中文；协议名、字段名等专有名词保留原文。
- 全局设置与服务器字段分区展示，避免把共享配置放进单条服务器里。
